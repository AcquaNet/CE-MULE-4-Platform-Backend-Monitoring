# Mule Application Logging (Fluent Bit → OpenSearch)

Complete guide for sending Mule application logs to OpenSearch through Fluent Bit, for apps on the
platform's runtime pools (Docker) and for CloudHub.

## Overview

```
Mule app (log4j2 "logs" Socket appender, JSON over TCP)
   │  Docker workers: log-ingest:5000 (inside the network)
   │  CloudHub:        <gateway>:9100  (APISIX stream proxy)
   ▼
Fluent Bit (service fluent-bit, network alias log-ingest, profile `logging`): token check, tenant_id, timestamp
   ▼
OpenSearch: mule-logs-YYYY.MM.DD (Mule events) / logstash-YYYY.MM.DD (anything else)
```

Pipeline steps, config files and health endpoint: [04-opensearch.md](04-opensearch.md#fluent-bit).

Commands below that use `.env` variables (`$OPENSEARCH_ADMIN_PASSWORD`, ...) need them loaded first:
`set -a; . ./.env; set +a`.

## Network Access

| From | Endpoint | Notes |
|------|----------|-------|
| Docker workers / containers | `log-ingest:5000` (TCP or UDP) | inside `ce-base-micronet` / `ce-base-network` |
| CloudHub, external runtimes | `<gateway>:9100` (TCP) | APISIX stream proxy → `log-ingest:5000` |

Fluent Bit's own ports are not published. Every event must carry `auth_token` = `LOG_INGEST_TOKEN`
(root `.env`, generated by `config/scripts/setup/generate-secrets.sh`).

## Mule Application Configuration

### Log4j2 Configuration File

The app's `src/main/resources/log4j2.xml` (in `git/CE-MULE-4-Platform-Backend-Mule`). `config/mule/log4j2.xml` is an
older template for other apps: same appender, settings in a `<Properties>` block (`${logs.host}`, `${logs.port}`,
`${logs.token}`), wrapped in an `Async` appender, no `worker_id`.

```xml
<Socket name="logs" host="${sys:logs.host:-log-ingest}" port="${sys:logs.port:-5000}" protocol="TCP" reconnectionDelayMillis="5000">
    <JsonLayout compact="true" eventEol="true" properties="true" stacktraceAsString="true">
        <KeyValuePair key="auth_token" value="${sys:logs.token:-${env:LOG_INGEST_TOKEN:-no-token}}"/>
        <!-- $$: resolved per event (a single $ is resolved once at startup) -->
        <KeyValuePair key="tenant_id" value="$${ctx:tenant_id:-unknown}"/>
        <KeyValuePair key="application" value="ce-mule-base"/>
        <KeyValuePair key="environment" value="${sys:mule_env:-local}"/>
        <KeyValuePair key="log_type" value="mule"/>
        <KeyValuePair key="worker_id" value="${env:WORKER_ID:-${sys:mule.worker.id:-unknown}}"/>
    </JsonLayout>
</Socket>
```

and `<AppenderRef ref="logs"/>` on the root logger.

### Configuration Properties

| Property (system) | Default | Description |
|-------------------|---------|-------------|
| `logs.host` | `log-ingest` | Fluent Bit host (CloudHub: the gateway) |
| `logs.port` | `5000` | Fluent Bit port (CloudHub: `9100`) |
| `logs.token` | env `LOG_INGEST_TOKEN` | Ingest token |

They are read as **system** properties (log4j `${sys:...}`), not as Mule configuration properties.

## Docker Deployment

Apps on the platform's runtime pools need no settings: the defaults point at `log-ingest:5000` and the
Runtime Manager gives every worker `LOG_INGEST_TOKEN` (`WORKER_LOG_INGEST_TOKEN` in `mule/docker-compose.yml`)
and `WORKER_ID` (= the container name, e.g. `mule-default-1`).

### Verification

```bash
# Fluent Bit up and healthy
docker ps --filter name=fluent-bit

# Recent Mule logs, per worker
docker exec opensearch curl -s -k -u "admin:$OPENSEARCH_ADMIN_PASSWORD" "https://localhost:9200/mule-logs-*/_search?size=0" \
  -H 'Content-Type: application/json' \
  -d '{"aggs":{"w":{"terms":{"field":"worker_id"}}}}'
```

## CloudHub Deployment

### Prerequisites (platform side)

1. The gateway reachable from CloudHub on **9100** (logs) and **9443** (traces): allow CloudHub's egress IPs
   in your firewall
2. A certificate CloudHub trusts on 9443 (`config/scripts/setup/setup-letsencrypt.sh`); the local CA from a
   fresh install is not trusted by CloudHub's JVM
3. `LOG_INGEST_TOKEN` and `OTLP_INGEST_TOKEN` from the root `.env`

### Configuration

Set in CloudHub Runtime Manager > the application > Settings > **Properties** (they become system
properties; see `src/main/resources/config/cloudhub.properties.example` in the Mule app):

```properties
# Logs -> APISIX :9100 -> Fluent Bit
logs.host=<gateway>
logs.port=9100
logs.token=<LOG_INGEST_TOKEN>
# loads config/cloudhub.properties; log field environment=cloudhub
mule_env=cloudhub
```

The trace (`otel.*`) properties are in [09-apm-integration.md](09-apm-integration.md#cloudhub).

CloudHub sets `mule.worker.id` (0, 1, ...), which the appender uses as `worker_id`.

### Verification

```bash
# From a machine outside the platform: the stream port answers
nc -zv <gateway> 9100

# Logs arriving from CloudHub
docker exec opensearch curl -s -k -u "admin:$OPENSEARCH_ADMIN_PASSWORD" "https://localhost:9200/mule-logs-*/_search?q=environment:cloudhub&size=3&pretty"
```

## Security

- **Token**: events without `auth_token` = `LOG_INGEST_TOKEN` are dropped by Fluent Bit (`pipeline.lua`); the
  token is removed before indexing. Rotate it in `.env`, restart `fluent-bit` and the Runtime Manager
  (workers pick it up), and update CloudHub's `logs.token`.
- **Network**: only the APISIX stream port 9100 is published; restrict it to CloudHub's egress IPs.
- **Transport**: 9100 is plain TCP (the token travels in each event). For untrusted networks put it behind
  a VPN/private link, or add TLS on the APISIX stream listener.

## Viewing Logs in OpenSearch Dashboards

Open **https://localhost:9443/dashboards/**, create an index pattern `mule-logs-*` with time field
`@timestamp`. The Runtime Manager's application overview also shows recent errors and warnings per app.

### Common Queries

```
application:"ce-mule-base"
worker_id:"mule-default-1"
level:"ERROR"
tenant_id:"acme-corp"
application:"ce-mule-base" AND level:"ERROR"
```

### Available Log Fields

| Field | Description | Example Value |
|-------|-------------|---------------|
| `application` | Application name | `ce-mule-base` |
| `environment` | Environment (`mule_env`) | `local-docker`, `cloudhub` |
| `worker_id` | Worker (container name / CloudHub worker) | `mule-default-1`, `0` |
| `tenant_id` | Tenant (normalized) | `acme-corp`, `unknown` |
| `tenant_id_original` | Raw value when it had to be cleaned | `Globex Inc!` |
| `level` | Log level | `INFO`, `WARN`, `ERROR` |
| `message` | Log message | `Processing request` |
| `loggerName` | Logger | `com.acqua.status` |
| `thread` | Thread name | `[MuleRuntime].uber.01` |
| `source_host` | Sender host (if sent) | |
| `@timestamp` | Event time (from log4j `instant`) | `2026-01-01T12:00:00.000Z` |

## Troubleshooting

### Logs Not Appearing

```bash
# Fluent Bit running and healthy (logging profile)
docker compose ps fluent-bit
docker compose logs fluent-bit | tail -30          # OpenSearch errors show here

# Send a test event (dropped without the token)
TOKEN=$(sed -n 's/^LOG_INGEST_TOKEN=//p' .env)
echo "{\"application\":\"test-app\",\"level\":\"INFO\",\"message\":\"test log\",\"auth_token\":\"$TOKEN\"}" | nc -w 2 localhost 9100

# From a worker
docker exec mule-default-1 bash -c 'echo > /dev/tcp/log-ingest/5000' && echo reachable
```

### CloudHub Can't Reach the Gateway

- `nc -zv <gateway> 9100` from outside; check the firewall allows CloudHub's egress IPs
- APISIX listener: `stream_proxy.tcp` has 9100 in `config/apisix/config/config.yaml`, route in `stream_routes`

### Events Dropped (Token)

- `.env` `LOG_INGEST_TOKEN` must equal the app's `logs.token` (CloudHub) or the workers' env
  (`docker exec mule-default-1 printenv LOG_INGEST_TOKEN`)
